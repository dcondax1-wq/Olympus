**Full title:** Zlarior eval size worked out state by state (dynamic programming, 2026-11-03 night) - far fewer dead evals at the same 2-week pass rate, but $18-34 a month less per slot, so it stays a lead

## Summary

The live eval size is one rule for every eval state (micros so one winner covers what is left to +$3,000, capped at 80% of the room). Tonight the size was solved for EACH state - balance, where the trailing floor sits, sessions left of the 10 - by backward induction on the 128 real Jan-Jun 2026 LIT sessions, choosing among 28 sizes (0.5-3x the one-winner size, 40-100% room caps) to maximise P(pass in 10) minus lam x P(fail in 10). The frozen tables were played through the real eval code on Jul-Oct 2026 and 2021-25. The lam 0.5 table sits on a better pass / fail frontier than every room-share setting (at the old safe set's fail rate it passes 2-4 points more evals in all three spans), and on the real 2026 order it cuts 2-week fails from 16-23% to 1-5% with the same pass rate. But the owner's money metric (the whole slot: eval -> funded -> payouts) is $18 / $34 / $3 a month lower than live, and passes take longer. The owner chose speed and money on 2026-10-25 (room 0.8, "evals: one hit, make it quick"), so nothing changes. Keep it as the replacement for the old safe set if he ever wants fewer dead evals. Paper only.
