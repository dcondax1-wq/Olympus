## Checked, no change needed
- **Folder path:** LE_Feed writes `Path.Combine(Globals.UserDataDir, "le_feed")`, which is `Documents\NinjaTrader 8\le_feed`
  following the OneDrive redirection (`C:\Users\dcond\OneDrive\Documents\NinjaTrader 8\le_feed`). The bot reads
  `default_folder()`, which uses `SHGetFolderPathW(CSIDL_PERSONAL)` (also redirected) first, then `~\Documents`, then
  `~\OneDrive\Documents`. `NO_CHART_MODE.bat` copies with `[Environment]::GetFolderPath('MyDocuments')`. All three agree.
- **DST (ended Nov 1):** there are no fixed UTC offsets and no naive `fromtimestamp` / `datetime.now()` in the live path. Everything uses
  `ZoneInfo("America/New_York")`, and LE_Feed's market-hours check uses `TimeZoneInfo` "Eastern Standard Time".
- **Windows file locks:** every state file is saved through `fsutil.replace` (retried). LE_Feed swaps files
  (`File.Replace`, with a copy fallback).
- **Disk full:** state saves write a `.tmp` file and then swap it in, inside try (the main file stays intact, and the error goes to `health.last_error`). LE_Feed logs and skips
  a bar it cannot append.
- **Dec 10 roll:** `nt_instrument()` switches MNQ 12-26 to 03-27 on ET date 2026-12-10 (00:00 ET, inside the CME day that
  began at 18:00 Dec 9, two hours before LIT's 02:00 entries). LE_Feed picks up the new `feed_instruments.txt` within 3 min and
  rewrites the files from the new contract's history. The roll guard refuses entries while the instrument file lags.
  For the owner's lead chat, not changed here (it is a decision-path change): rolling at 18:00 ET instead of midnight would keep one
  contract for the whole CME day.
- **Duplicated helpers (left as is, flagged):** the outgoing connection files are parsed in four places
  (`NinjaTraderAdapter.connections`, `ops_checks.nt_connections`, `botctl.folder_probe`, `nt_log.outgoing_summary`). Each now
  passes its result through `connection_view`. Merging the parsers is a safe follow-up but touches the order path's cache.
