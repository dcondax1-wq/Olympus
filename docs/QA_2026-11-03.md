## Checked, no change needed
- **Folder path:** LE_Feed writes `Path.Combine(Globals.UserDataDir, "le_feed")`, i.e. `Documents\NinjaTrader 8\le_feed`,
  which follows the OneDrive redirection (`C:\Users\<you>\OneDrive\Documents\NinjaTrader 8\le_feed`). The bot reads
  `default_folder()`: `SHGetFolderPathW(CSIDL_PERSONAL)` (also redirected) first, then `~\Documents`, then
  `~\OneDrive\Documents`. `NO_CHART_MODE.bat` copies with `[Environment]::GetFolderPath('MyDocuments')`. All three agree.
- **DST (ended Nov 1):** no fixed UTC offsets and no naive `fromtimestamp` / `datetime.now()` in the live path; it uses
  `ZoneInfo("America/New_York")` throughout, and LE_Feed's market-hours check uses `TimeZoneInfo` "Eastern Standard Time".
  CME's DST switches fall on Sunday 02:00, when the market is closed, so no real bar sits in a gap or overlap (fix 9 is a
  belt for a non-US display zone).
- **Windows file locks:** every state file is saved through `fsutil.replace` (retried). Order files reach `incoming\` in one
  rename. LE_Feed swaps whole files (`File.Replace`, with a copy fallback).
- **Disk full:** state saves write a `.tmp` file and then swap it in, inside try (the main file stays intact; the error goes
  to `health.last_error`). LE_Feed logs and skips a bar it cannot append.
- **Dec 10 roll:** `nt_instrument()` switches MNQ 12-26 to 03-27 on ET date 2026-12-10 (00:00 ET, inside the CME day that
  began at 18:00 Dec 9, two hours before LIT's 02:00 entries). LE_Feed picks up the new `feed_instruments.txt` within 3 min
  and rewrites the files from the new contract's history. The roll guard refuses entries while the instrument file lags.
  For the owner's lead chat, not changed here (it is a decision-path change): rolling at 18:00 ET instead of midnight
  would keep one contract for the whole CME day.
- **Left as is (flagged):** the adapter's cached `connections()` (order path) and `botctl.folder_probe` (which reads
  positions in the same pass) keep their own readers; both now pass the result through `connection_view`.
  `tools/atlas_conf.py` and `tools/atlas_lit_armed.py` both write `atlas_lit_armed.pkl` with slightly different
  fields (research only; `bholds.py` overrides that path, so it was not re-keyed here).
