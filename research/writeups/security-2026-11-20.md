## The integrity fix (free, no account)
The PC keeps an ECDSA P-256 key. Each public post ends with `,"sg":"<signature of the exact text before it>"}`, so Python and the
phone's WebCrypto check the same bytes and old readers ignore the extra field. The public key `vk` is pinned once in
`status_feed.json`. Until then, a post more than 10 minutes in the future is never believed, and Claude's board labels the feed's
events `[ntfy-unsigned]`. Trade-off: until the vk is pinned, real owner notes that reach Claude only through the status channel are
labelled too and not counted as "not answered" (they still show in the events).

## Rejected / not done
- ntfy access tokens: they need an ntfy account, and the site would have to ship a read token anyway. Signatures cost nothing.
- HMAC with a shared key: a key the site can verify with is a key anyone can sign with. Public-key signatures instead.
- The Pages repo's own git history: outside this session's GitHub scope, not checked.
